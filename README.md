# MT5700M Manager for OpenWrt

[![CI](https://github.com/FAN789/luci-app-mt5700m/actions/workflows/ci.yml/badge.svg)](https://github.com/FAN789/luci-app-mt5700m/actions/workflows/ci.yml)

面向鼎桥（TD Tech）MT5700M-CN 5G 模组的 OpenWrt LuCI 管理插件。
当前发布版本 **v3.0.8**：应用 `3.0.8-r1`，原生传输程序 `1.0.1-r1`。
这是插件包，不是整机固件，不包含个人网络配置、短信、SIM 数据或登录凭据。

## 3.0.8 更新

- 修复连接设置与模组实际协议混淆（#10）：分别显示“已保存的 IP 协议”和“模组 IP 协议（快照）”；不一致时提示，查询失败显示未知，不把保存值冒充实际值。模组值复用已有连接查询缓存，不新增周期 AT 采集。
- 自动 NDIS 恢复不再调用拨号配置写入事务。恢复前只读核对模组与保存的完整拨号配置；不一致或读回失败时保留模组设置及当前接口，不执行断开／重拨，并受同一恢复预算限制。状态分别为 `profile-mismatch` / `profile-unconfirmed`，日志不包含 APN、用户名或密码。
- 主动“连接／重拨”仍按保存配置应用到模组，但操作前明确确认。手工 AT 修改后，可在连接设置中修改并保存相同协议；保存本身不会向模组写入协议。没有新增自动导入或覆盖用户配置的逻辑。
- 重新验证 #6–#9 的主题隔离、窄屏布局、流量分行、NAT 健康探测、启动超时后实际联网确认，以及健康／NDIS 共享恢复间隔和预算；保留五秒共享信号缓存和短信串行化、不自动重发行为。
- 新增完整拨号配置一致性、未知／超时拒绝、自动恢复零配置写入及页面协议状态回归；原生传输程序版本仍为 `1.0.1-r1`。

正常联网且 carrier 存在时不会为了对比设置额外查询 AT。carrier 丢失时，自动恢复仅在保存配置与模组读回一致的前提下恢复数据会话；首次配置或手动修改模组后，请明确选择保存配置或模组配置，必要时主动连接。高级模组拨号控制和普通连接设置仍是两个不同配置入口，前者不会隐式改写后者。

本次完整 Linux 回归和 19 项原生传输测试通过；在 H5000M 的 BusyBox 环境隔离运行健康、配置差异与会话恢复回归，真实 AT 只读回读及蜂窝 HTTPS 通过，未改动生产配置或重拨。使用 Argon v2.4.8 的真实 CSS 对代表性页面 DOM 做深浅色、1440/820/390px 浏览器回归，标题透明白字、伪元素隔离、3/2/1 分栏、流量分行和复选框均通过；这不等同于所有 LuCI 页面和主题配置的完整实机验收。未发送／删除短信、重启模组或刷固件。

## 3.0.7 更新

- 新增独立 `mt5700m-signal` 后台服务，正常约每 5 秒采集一次信号并原子发布到 root-only tmpfs 缓存。多个页面共享同一采样，页面读缓存不再直接发送 AT；完整状态快照也复用信号缓存。
- 管理器不再周期预热完整状态/会话快照；正常 USB 设备与接口配置未变化时跳过完整同步，避免监控循环额外读 AT 或重复配置网络。启动、明确重载以及实际设备变化仍保留同步。
- 信号为低优先级操作：短信或设置占用控制通道时立即跳过，不排队；连续采集失败逐步延长间隔至最多 30 秒，成功后恢复正常周期。保留串口同步、超时隔离及短信发送确认机制，不自动重发短信。
- 页面每 5 秒读缓存，隐藏/离开后暂停页面请求；后台采集不依赖浏览器。按真实采样时间显示新鲜度，15 秒以上提示延迟，超过 30 秒或尚无缓存时显示不可用，不伪造“刚更新”。
- 右上角连接状态与刷新按钮统一为 36px 高度，垂直居中并保持固定间距。
- 优化管理页字体层级、行高与数字对齐，统一标题、正文、辅助标签及关键数值；样式只作用于本插件，使用本机系统字体，不加载在线字体。
- 新增共享缓存、并发读取、锁占用、失败保留、重试退避和页面计时回归。APK 构建采用官方 OpenWrt 25.12.6 SDK，继续提供 24.10.8 SDK 的 IPK。

信号采集仍通过 AT；当前实现不是模组主动推送，也不等同于 QMI/SDK。5 秒是正常调度目标，指令耗时、锁占用和退避可能延长成功采样间隔。温度、其他完整状态字段及联网恢复逻辑不在本次统一信号采集范围。

本版对应改动已在 H5000M / OpenWrt 25.12.6（Linux 6.12.112）运行观察约 2 分钟：链路与健康状态保持正常、蜂窝 HTTPS 通过、无新增 USB 复位或掉线，短信相关只读查询正常。未为本次验证发送或删除短信；此结果不是长期吞吐、冷启动或端到端短信送达验收，也不是尚未生成的发布包安装验收。

## 3.0.4 更新

- 修复 NAT 模式健康误判（#8）：不再要求蜂窝 PDP 地址与主机 DHCP 地址相等；以绑定蜂窝接口的 IPv4 HTTPS 探测为准。AT 地址暂时不可读也不再否决已经验证的联网结果。
- 修复启动同步反复断链（#9）：已有 carrier 时先验证实际联网，不因 `/var/run` 同步标记缺失直接断开。自动启动恢复和健康恢复共用至少 180 秒间隔、每小时最多 3 次的预算。
- NDIS 启动返回超时并不等于成功或失败：只发一次启动命令，拉起主机接口后在最多 30 秒的宽限时间内观察地址、carrier 和实际 HTTPS，探测耗时计入宽限。只有验证成功才写同步标记；失败保留步骤/返回码并进入冷却，不自动反复重发。
- 修复 Argon 标题背景/伪元素冲突（#6），放宽插件页面宽度、统一辅助文字可读性、调整窄屏分栏与频段复选框（#7）。流量下载/上传分两行并补充中文翻译；样式仅作用于本插件。
- 增加 NAT、启动超时确认/未确认、共享恢复预算和 UI 样式/翻译回归测试。模拟测试不等于所有运营商、主题或模组固件均已完成长期实机验收。

## 历史版本说明

3.0.3 为 SDK 刚生成的未签名 APK 执行显式签名和严格验签，修正 3.0.2 的签名输入处理；不要使用 3.0.1 的未签名 APK。

- 自有 C 程序 `mt5700m-transport` 负责串口/TCP AT 和短信传输；运行时不再依赖 `ubus-at-daemon`、`sms-tool_q` 或 QModem 服务。
- 按 MT5700M 命令格式修复短信发送；后台发送任务显示进度和明确结果，确认不明时不自动重发，以免重复发送和计费。

- 整个模组操作串行化、缓存发布锁、串口同步探测及超时隔离，降低并发操作和迟到响应造成的误判。
- APN/自动拨号变更先保存旧配置，写入后核对；失败或中断后使用持久日志恢复。
- 区分“数据链路已连接”和“互联网验证通过”；仅在连续实际联网失败后按条件续租/恢复数据会话。NAT 两侧地址不一致不是单独的恢复依据。
- 修复 BusyBox 环境等待兼容性和服务实例管理；短信空间接近满额时提示，不自动删除旧短信。
- 新安装默认使用蜂窝 IPv4/IPv6 双栈。升级保留已有用户配置，不强制覆盖 PDP/APN。运营商是否提供 IPv6 取决于 SIM、APN 与网络。

## 功能与边界

提供信号、载波聚合、模组/SIM 状态、APN/PDP、连接与重拨、网络制式与频段、小区查询、短信、流量历史、温度缓存及 AT 终端。
流量历史保存在 `/etc/mt5700m/traffic-history`；短信发送历史为浏览器本地记录，支持现有导入/导出功能，不是跨设备同步服务。

蜂窝 WAN IPv6 与 LAN IPv6 分发是不同设置。插件不擅自开启或禁用 LAN 的 RA/DHCPv6/NDP，也不替用户改变代理软件的 IPv6 策略。
健康检查使用蜂窝接口访问公共 HTTPS 端点；不提交短信、身份信息或凭据，但端点会像普通网页访问一样看到来源 IP。
当前健康检查不是独立的 IPv6 可达性验收；不能把健康状态当成所有 IPv6 目的站点均可达的保证。

H5000M + KWRT（Linux 6.12.108）实机已验证 AT 查询、管理服务自启动、蜂窝 IPv4 HTTPS、断线/租约恢复、APN 失败回滚、整机重启及断电冷启动。

自动测试包含 19 项原生传输模拟测试、shell 回归、共享信号采集/缓存、UI 计时与字体、错误处理、短信解码/任务、健康恢复和配置回滚测试。

修改频段、SIM/PIN、固件或发送短信前，应明确了解断网、数据丢失和计费风险。

## 安装

在 [Releases](https://github.com/FAN789/luci-app-mt5700m/releases) 下载对应构建的归档并核对 SHA256。
自动构建提供 `mediatek/filogic` 的两套独立产物：OpenWrt 24.10.8 SDK 的 IPK，以及 25.12.6 SDK 的 APK。
每套包含应用、简体中文包、`mt5700m-transport` 和校验文件；APK 构建另附签名公钥。
原生传输包面向 `aarch64_cortex-a53`；LuCI 页面虽为架构无关包，仍依赖匹配的原生传输包。

1. 备份配置，确认设备架构、libc/用户空间 ABI 和包管理器。不要同时安装 IPK/APK，不要强制跳过依赖。
2. 从**当前固件的软件源**安装 USB 驱动：`kmod-usb3`、`kmod-usb-serial`、`kmod-usb-serial-option`、`kmod-usb-net`、`kmod-usb-net-cdc-ether`、`kmod-usb-net-cdc-ncm`。不得跨内核复制驱动。
3. 确认有 `luci-base`、`flock`、`curl` 与 DHCPv6 客户端 `odhcp6c`。`curl` 用于联网健康探测；缺少时不会盲目触发网络恢复。
4. 安装对应格式的传输包、应用包和中文包。APK 公钥只应在核对来源后加入系统信任目录，不要使用跳过签名检查选项。
5. 停止其他会占用同一 AT 串口的模组管理服务，再在 LuCI 中配置并启用本插件。首次启用或升级可能触发拨号，需预留维护窗口。安装后确认 `mt5700m-signal` 服务启用；刷新已打开的页面以加载新界面。

KWRT 等衍生固件可能保留不同包格式/依赖版本，不能仅凭版本名称判断兼容性。自动发布包仍需在目标系统确认依赖；实机验证不等于所有衍生固件通用认证。

## 源码编译与自动发布

```sh
git clone https://github.com/FAN789/luci-app-mt5700m.git
cp -a luci-app-mt5700m/luci-app-mt5700m /path/to/openwrt/package/
cp -a luci-app-mt5700m/mt5700m-transport /path/to/openwrt/package/
cd /path/to/openwrt
make menuconfig
# LuCI -> Applications -> luci-app-mt5700m
make package/mt5700m-transport/compile V=s
make package/luci-app-mt5700m/compile V=s
```

推送与 PR 运行 CI；推送匹配应用版本的 `v*` 标签会先执行测试，再通过官方 SDK 自动编译并发布 Release。
手动运行 Build Release 只保存 Actions 产物，不创建版本。SDK 下载校验和及构建信息随产物保留；签名私钥不发布。
`scripts/build-native-preview.py` 仅用于本地实验包，不能替代 SDK 正式构建与目标系统验收。
